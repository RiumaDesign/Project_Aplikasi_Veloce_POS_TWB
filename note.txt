[ 1. INFORMASI UMUM & SCOPE KERJA PRAKTIK ]
================================================================================

1.1 Latar Belakang Penugasan:
--------------------------------------------------------------------------------
PT Taman Wisata Borobudur mengoperasikan berbagai titik penjualan makanan/minuman di kawasan destinasi Candi Borobudur , mencakup:
- 9 Unit Vending Machine otomatis (VM 1 sampai dengan VM 9).
- 2 Titik Outlet fisik (Outlet Museum Samudra Raksa & Outlet Refreshment Barat).
- 1 Hub Distribusi logistik (Gudang Pusat Borobudur).

Aplikasi kasir awal (baseline) memiliki keterbatasan arsitektur:
1. Kolom stok bersifat flat/hardcode (`stok_pos_a`, `stok_pos_b`), tidak dapat
   menampung penambahan 11 lokasi baru tanpa mengubah skema tabel berulang kali.
2. Tidak adanya master lokasi/outlet dinamis.
3. Rincian transaksi hanya disimpan dalam bentuk teks string (`item_singkat`).
4. Belum tersedianya sistem mutasi Delivery Order (DO) antar lokasi mesin/outlet.
5. Belum ada pencatatan terpisah untuk barang retur fisik rusak dan kadaluarsa.
6. Antarmuka masih monolitik dan belum mengadopsi standar visual modern Glassmorphism.

1.2 Ruang Lingkup Kerja Praktik (Scope of Work):
--------------------------------------------------------------------------------
1. Audit arsitektur codebase eksisting dan penyusunan laporan pra-perubahan.
2. Rekonsiliasi database relasional multi-lokasi tanpa menghilangkan data historis.
3. Dekomposisi arsitektur monolitik menjadi modular (Pemisahan Controller & View).
4. Penambahan Master CRUD 11 Lokasi Outlet & Vending Machine.
5. Fitur Master Produk Lengkap (Full CRUD Produk & Upload Foto):
   - Tambah produk baru beserta upload berkas foto produk (JPG/PNG/WebP).
   - Edit data produk (nama, harga jual, tipe varian, stok) dan penggantian foto.
   - Hapus produk terintegrasi dengan pembersihan file gambar fisik dari server.
   - Pengaturan ketersediaan produk per outlet (Many-to-Many via `product_outlets`).
6. Pembaruan Terminal Kasir POS berbasis sesi outlet aktif dan rincian transaksi_detail.
7. Modul mutasi stok Delivery Order (DO) multi-arah (Gudang ➔ Outlet dan Antar-Outlet).
8. Modul pengelolaan barang rusak (fisik, kemasan, expired) dengan alokasi karantina.
9. Pembaruan grafik omzet dan analitik stok realtime multi-outlet (Chart.js).
10. Fitur Export Laporan (Excel/CSV & PDF) dengan pencatatan audit export_logs.
11. Integrasi Mobile Web App Native-Like (PWA / Mobile-Optimized Interface):
    - Pengelolaan dashboard admin, monitoring stok, dan terminal kasir via smartphone & tablet.
    - Kesiapan tata letak touch-friendly, manifest web app, dan REST API terstruktur (`api.php`).
12. Penyempurnaan UI/UX berbasis Glassmorphism modern khas PT Taman Wisata Borobudur.
13. Uji fungsional menyeluruh, UAT bersama staf operasional, serta penyusunan laporan dan dokumentasi teknis pembuatan aplikasi.

     stok_gudang - FLAT!)       item_singkat teks)      kirim_pos_a/b)

2.2 Struktur Basis Data Eksisting (4 Tabel Awal):
--------------------------------------------------------------------------------
1. `produk` :
   - Kolom: `id`, `nama`, `harga`, `custom_type`, `gambar`, `stok_gudang`, `stok_pos_a`, `stok_pos_b`.
   - Celah: Kolom stok bersifat horizontal (`stok_pos_a`, `stok_pos_b`). Tidak scalable karena jika
     menambah 11 outlet baru, pengembang terpaksa menambah 11 kolom (`stok_vm1`, `stok_vm2`, dst).
2. `transaksi` :
   - Kolom: `id`, `id_transaksi`, `tanggal`, `waktu`, `petugas`, `pos_aktif`, `metode`, `item_singkat`, `total_harga`.
   - Celah: Ketiadaan relasi ID outlet (hanya string statis `'POS A'`). Rincian pembelian hanya disimpan
     dalam string teks agregat (`item_singkat`), sehingga menyulitkan kalkulasi omzet per produk.
3. `log_stok` :
   - Kolom: `id`, `id_produk`, `tipe_aktivitas`, `jumlah`, `tanggal_log`.
   - Celah: Kolom `tipe_aktivitas` dikunci menggunakan ENUM('tambah_gudang','kirim_pos_a','kirim_pos_b').
     Sistem tidak dapat mencatat mutasi ke 9 vending machine maupun transfer antar-outlet.
4. `kasir` :
   - Kolom: `id`, `nama`, `password`, `role`.
   - Celah: Akun kasir belum terhubung secara formal ke master shift atau lokasi penugasan.

2.3 Ringkasan Kendala Utama Sistem Lama:
--------------------------------------------------------------------------------
- Skema Stok Kaku (Horizontal Anti-Pattern): Tidak mendukung multi-outlet dinamis.
- Monolitik & Rawan Konflik: Kode bisnis, query database, dan tampilan HTML bercampur aduk.
- Duplikasi Login: `index.php` dan `login.php` memiliki dua form otentikasi terpisah.
- Ketiadaan Fitur DO Antar-Lokasi: Distribusi barang hanya satu arah dari gudang ke 2 POS.
- Nihil Pelacakan Barang Rusak/Expired: Barang cacat tidak memiliki pencatatan resmi.
- Tidak Ada Kontrol Ketersediaan Produk: Seluruh menu otomatis tampil di semua kasir.

3.2 10 Poin Utama Perubahan yang Dilakukan:
--------------------------------------------------------------------------------
1. Perbaikan Grafik Penjualan & Omzet Real-Time:
   - Mengalihkan kalkulasi grafik dari agregat kasar ke data terstruktur `transaksi_detail`.
   - Menyajikan grafik komparasi stok multi-lokasi, omzet per kasir, dan tren 5 produk terlaris.
2. Penambahan Master 11 Lokasi Mesin & Outlet:
   - Mendukung 9 Vending Machine (VM-01 s/d VM-09) dan 2 Outlet fisik (Museum & Barat).
   - Menggunakan tabel relasional `locations` dinamis dengan kolom status operasional.
3. Fitur Tambah / Edit POS (CRUD Master Outlet):
   - Antarmuka visual admin untuk menambah, mengubah nama/kode unit, serta toggle aktif/nonaktif.
   - Otomatis menginisialisasi slot stok pada tabel `stok_lokasi` saat outlet baru dibuat.
4. Kategori Retur Rusak & Expired:
   - Klasifikasi retur: Rusak Fisik / Bocor, Expired / Kadaluarsa, dan Kemasan Rusak.
   - Form pencatatan lengkap disertai alasan, tanggal, dan identitas petugas.
5. Pengembangan Delivery Order (DO) Antar Lokasi:
   - Mendukung mutasi dua arah: Gudang ➔ Outlet/VM serta Antar-Outlet/VM.
   - Penomoran surat jalan DO otomatis berformat `DO/YYYYMMDD/XXXX`.
6. Pengelolaan Barang Rusak & Alokasi Karantina:
   - Pemisahan fisik stok barang rusak agar tidak bercampur dengan stok layak jual kasir.
   - Pengurangan stok normal dan penambahan counter `stock_damaged` / `stock_expired`.
7. Tabel Log Histori Retur & Barang Rusak:
   - Tabel visual pemantauan barang retur di dashboard admin untuk memudahkan audit inventori.
8. Log Export PDF & Excel:
   - Fitur ekspor laporan rekapitulasi penjualan, mutasi DO, dan retur ke format Excel/CSV & PDF.
   - Pencatatan jejak audit pengunduhan pada tabel `export_logs`.
9. Standarisasi Tampilan UI Berbasis Glassmorphism:
   - Tampilan modern dengan efek translucent glass, ambient blur glow, dan tipografi Plus Jakarta Sans.
   - Desain terpadu, ergonomis, dan responsif untuk kenyamanan kasir dan manajemen.
10. Fitur Master CRUD Produk & Upload Multi-Media Lengkap:
    - **Create (Upload Produk):** Form penambahan item produk baru meliputi nama produk, harga jual,
      tipe/varian (opsi suhu), stok awal gudang, dan upload foto produk (JPG/PNG/WebP) dengan
      penamaan acak unik berbasis timestamp guna mencegah bentrok nama berkas di direktori `uploads/`.
    - **Read (Katalog & Preview):** Tabel visual produk di dashboard dengan thumbnail preview gambar,
      status stok, harga, serta label ketersediaan outlet.
    - **Update (Edit Produk & Ganti Foto):** Pengubahan nama, harga, stok, ketersediaan outlet, serta opsi
      pergantian foto produk baru yang otomatis menghapus berkas foto usang dari server (*orphan file cleanup*).
    - **Delete (Hapus Produk & Berkas Gambar):** Penghapusan produk yang terintegrasi untuk menghapus
      berkas fisik di folder `uploads/` serta membersihkan relasi terkait di `stok_lokasi` dan `product_outlets`.
    - **Logika Ketersediaan Outlet (Many-to-Many):** Penentuan ketersediaan menu per titik penjualan
      melalui tabel relasi `product_outlets` (Tersedia di Semua Outlet atau Pilihan Tertentu).
11. Integrasi Mobile Web App Native-Like (Akses Fleksibel Smartphone & Tablet):
    - Penyusunan antarmuka Mobile-First responsif agar koordinator lapangan, supervisor, dan staf dapat
      memantau stok, menyetujui mutasi DO, dan memeriksa omzet langsung dari smartphone tanpa harus
      membuka laptop/PC di area wisata candi.
    - Dukungan Progressive Web App (PWA) dengan manifest PWA dan meta tag native-feel (full-screen, touch gesture).
    - Arsitektur backend `api.php` yang siap bertindak sebagai REST API gateway jika di kemudian hari
      diintegrasikan ke aplikasi mobile native (Android / iOS).
